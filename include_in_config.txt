/* Selector is `.reveal .slides section img`, NOT a bare `img`, and that is
 * load-bearing, not stylistic: every bundled reveal.js theme
 * (dist/theme/*.css) ships its own
 *   .reveal img, .reveal video, .reveal iframe { max-width: 95%; max-height: 95%; }
 * at specificity (0,1,1) (one class + one element). A bare `img { ... }`
 * rule here is only (0,0,1) -- lower specificity always loses the cascade
 * to the theme's rule *regardless of which file loads later or what value
 * you put here*, so every previous version of this rule (in vh, then in a
 * fixed px) silently never took effect at all. Confirmed via computed
 * style in a real headless-Chrome render (getComputedStyle(img).maxHeight
 * still reported the theme's "95%", not this file's value) -- grepping the
 * built HTML for your chosen value proves the rule exists in some
 * stylesheet, not that it won the cascade. `.reveal .slides section img`
 * is (0,1,3), high enough to beat the theme rule outright without needing
 * `!important`. (The theme's own max-height:95% is also frequently a
 * no-op even when it does win: percentage max-height only resolves against
 * a containing block with a *definite* height, and a content-sized
 * `section` usually isn't one -- so it silently computes to "none",
 * leaving the image's height bound only by its intrinsic aspect ratio at
 * whatever width it renders, which is how a wide/short source PNG ends up
 * rendering taller than the whole slide.)
 *
 * max-height is in em, not vh or px -- vh resolves against the real
 * browser viewport, not reveal.js's fixed local canvas coordinate space
 * (the revealjs: width/height in mkslides.yml) that gets uniformly
 * transform: scale()'d to fit, so a vh-sized image overflows past the
 * slide's actual (scaled-down) height whenever the viewer's window is
 * narrower than the deck's configured canvas aspect ratio. em stays in
 * the local coordinate space (relative to the section's font-size,
 * default theme --r-main-font-size: 42px) so it scales proportionally
 * with everything else, AND -- unlike a fixed px value -- it shrinks
 * along with fit_text.js's per-slide font-size reduction on overflowing
 * slides, so an oversized image on a text-heavy slide gets scaled down
 * too, not just left alone while the text shrinks around it. 11em ~= 462px
 * at the default 42px base font size; retune if a project overrides
 * --r-main-font-size or needs more/less headroom for surrounding text. */
.reveal .slides section img {
  max-width: 100%;
  max-height: 11em;
  object-fit: contain;
  display: block;
  margin: 0 auto;
}
